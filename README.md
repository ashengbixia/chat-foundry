# chat-foundry

基于 Vue 3 和 FastAPI 的 AI 聊天学习项目。

## 环境与依赖安装

当前后端开发环境为 Python 3.10.20。建议使用独立的 Python 3.10 虚拟环境，不要复用装有其他项目依赖的大环境。
前端需要 Node.js `^22.18.0 || >=24.12.0`，与 `frontend/package.json` 中的要求一致；可选择满足要求的 Node 22 或 Node 24 版本。

以下命令使用 Windows CMD，从下载后的项目根目录执行，不要求文件夹名称与 GitHub 仓库名一致。

### 安装后端依赖

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

先确认这里的 `python` 是准备使用的 Python 3.10。清单固定了当前项目使用的直接依赖及配置读取依赖，间接依赖由 pip 解析，不是当前 Conda 环境的全部包列表。

### 安装前端依赖

```bat
cd frontend
npm ci
```

`npm ci` 根据已提交的 `package-lock.json` 安装，不需要提交 `node_modules`。

## 后端模型配置

模型配置统一由 `backend/app/core/config.py` 读取，密钥不要写进源码、前端或 HTTP 测试文件。

可选择以下任一方式：

1. 在 PyCharm 的后端运行配置中设置环境变量 `LLM_BASE_URL`、`DEEPSEEK_API_KEY`、`LLM_MODEL`、`LLM_TIMEOUT`。
2. 在启动后端的终端设置这些环境变量，然后在同一终端启动后端。
3. 本机开发时，将 `backend/.env.example` 复制为 `backend/.env`，填写真实配置。

环境变量优先于 `.env`，未提供的配置使用代码默认值。配置在进程启动时读取，修改后需要重启后端。

密钥统一使用 `DEEPSEEK_API_KEY`，不再读取旧名称 `LLM_API_KEY`；如果本机 `.env` 仍使用旧名称，请改名，其他配置保持不变。

`LLM_BASE_URL` 是聊天补全 API 的基础地址，程序会追加 `/chat/completions`；服务要求 `/v1` 时，应将它包含在基础地址中。

例如使用 DeepSeek 时，可在项目根目录的 CMD 终端设置以下进程环境变量。密钥必须替换为自己的值，不要把真实值写进本文档或提交到 Git：

```bat
set "DEEPSEEK_API_KEY=替换为自己的密钥"
set "LLM_BASE_URL=https://api.deepseek.com"
set "LLM_MODEL=deepseek-chat"
set "LLM_TIMEOUT=60"
.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

这些 `set` 命令只对当前 CMD 及其启动的子进程生效。使用 PyCharm、PowerShell 或新的终端时，请在对应运行环境中配置，不能假设它们自动共享刚才的进程变量。

`.env` 是本机明文配置文件，不是加密存储；环境变量也不是加密保险箱。不要分享配置截图、打印密钥或将密钥放在 `VITE_` 前缀的前端变量中。

## 启动和验证

后端保持运行，另外打开一个终端，从项目根目录启动前端：

```bat
cd frontend
npm run dev
```

前端默认代理到 `http://127.0.0.1:8000`，打开 Vite 终端显示的页面地址。后端健康检查为 `http://127.0.0.1:8000/health`，接口文档为 `http://127.0.0.1:8000/docs`。

没有数据库时，正常启动后端会创建 `backend/data/app.db` 和当前模型声明的表，并登记当前迁移版本，得到空的聊天数据。不能恢复原作者的会话和上传资料。

启动时会检查迁移版本、实际表结构和外键数据。版本落后时拒绝启动，并提示先停止后端，在项目根目录执行：

```bat
python -m backend.app.core.db_setup --upgrade
```

该命令先在数据库同目录创建 `app-before-upgrade-时间-随机值.db` 备份，再执行迁移，完成后重新启动后端。普通代码更新无需升级数据库。只检查当前状态也可以执行 `python -m backend.app.core.db_setup`。全新库通过应用启动或此命令初始化，不要直接运行旧的初始 Alembic 迁移。

已有库缺少版本、出现未知版本、表结构不匹配或无效外键时会报错，不会自动修改版本或修复数据。初始化中断若留下无版本表，也需要先备份并人工确认。升级失败会显示备份位置，不自动覆盖当前库；应停止使用并检查原因。

本清单来自当前开发环境及源码依赖核对，尚未完成全新环境安装和端到端验收；它不是跨平台完全锁定或生产部署安全审核的承诺。

## 账号、登录与数据隔离

当前数据库迁移版本为 `b3e8a1c6d054`。已有项目先停止后端，在项目根目录执行 `python -m backend.app.core.db_setup --upgrade`；升级命令会先备份数据库。升级完成后重新启动前后端，首次进入页面会要求设置管理员的用户名和密码，没有预置通用密码。首次初始化应由项目拥有者完成，之后再开放给其他人访问。

用户名不区分大小写，新注册用户名为1～80个非空白字符。注册和初始化时显示名称默认使用用户名，不单独填写，之后可在“我的账号”修改。旧版本已用邮箱注册的账号保留原登录字符串作为用户名，账号ID、密码、权限、会话与资料归属不变。

初始化时，全部未分配的旧会话和附件会在同一个事务内归第一个账号所有，消息、工具结果、引用快照和向量ID保持不变。数据库迁移本身不会创建账号或设置密码。后续普通用户可以自行注册并立即使用；注册时勾选申请管理员，或在“我的账号”提交申请，都只记录申请，必须由现有管理员在“用户管理”批准后才获得权限。

账号菜单支持修改显示名称、修改密码、退出登录及申请管理员。管理员可以查看账号列表、批准或拒绝管理员申请、降为普通用户、停用或恢复其他账号；不能修改自己的权限，不能通过管理入口读取其他账号的私人会话和资料。停用不删除账号历史。登录只需要用户名和密码，不要求邮箱。当前不包含密码找回、第三方登录或公开资料分享。

会话和文件列表按登录账号过滤；所有带ID的查询、消息分页、重命名、删除、生成回答、正文、切片和索引接口均检查所有权，越权统一返回404。保存消息时还会核对附件与会话属于同一用户，检索继续只使用真实消息附件范围。旧引用快照属于原会话，其他账号不能直接读取原文件。

密码使用随机盐和scrypt摘要保存；登录使用HttpOnly、SameSite=Strict的随机会话Cookie，数据库只保存Token摘要与过期时间。默认有效7天，可配置 `AUTH_SESSION_DAYS`（1～30天）。退出撤销当前会话；改密码撤销全部旧会话并为当前浏览器签发新凭证；停用账号撤销全部会话。账号状态在每次请求时重新核对，注册、登录和密码校验有单进程限流。

本机HTTP开发使用 `AUTH_COOKIE_SECURE=false`；HTTPS部署设为true，反向代理需保留浏览器请求的Host并正确传递协议，以通过同源写入检查。Vite已配置保留Host；修改代理配置后需重启前端开发服务。未登录不能使用聊天与文件API，健康检查和账号初始化状态查询仍公开。

刷新页面时从服务器恢复身份，不在localStorage保存密码、Token或用户资料。浏览器仅按用户ID保存上次会话ID；退出或切换账号会中止回答、销毁旧聊天仓库并卸载文件组件，其他标签页也会同步身份变化。私人API响应禁止缓存。数据库现在包含账号密码摘要和登录会话信息，继续保持 `backend/data`、`.env` 和备份不提交Git。

## 聊天界面

页面使用左侧会话导航、中间聊天区和按需展开的资料面板。窄屏自动收起导航，切换会话成功后关闭侧栏；文件面板关闭时保留当前上传和预览状态。会话重命名、删除收在每条会话的更多操作中。设置入口已开放“模型服务”，顶部显示当前账号实际使用的模型并可点击进入设置；底部显示真实登录用户，可打开“我的账号”、用户管理（管理员）和退出登录。

输入框支持多行、自适应高度，Enter 发送、Shift+Enter 换行，中文输入法选词时不会发送。输入区左下角“＋”直接选择TXT并上传，上传成功自动加入本次问题，最多3份、每份5MB；资料管理面板继续用于历史文件管理。空白页可以先输入和添加附件，首次发送自动创建会话并保留草稿。输入区右下角提供当前服务的模型快捷选择，切换成功后影响下一次回答，生成过程中发送按钮切换为停止按钮。

助手正文使用 Markdown 排版，支持标题、列表、代码和表格。原始 HTML 禁用，代码和用户消息按文字转义；Markdown 图片显示为文字，不自动请求外部图片地址。当前不提供代码语法高亮。

## 模型流式结束判断

模型流必须收到 `[DONE]` 才能正常结束；同时检查 `finish_reason`，区分普通回答、工具调用、长度截断和服务中止。兼容未提供 `finish_reason` 但返回有效正文或工具调用及 `[DONE]` 的服务。

提前断流、长度截断、空回答或不一致的结束信息会标记为失败，保留已有正文和工具记录，并在页面显示明确说明；不完整的工具调用流不会执行工具。主动停止继续保存为 `cancelled`，不会被当成异常断流。

## 模型输入预算

工具结果接近输入上限时会进入仅汇总阶段，收起工具定义，为最终回答腾出空间；不会删除模型服务要求回传的思考内容。若必要输入仍超限，会保存失败阶段和错误编号，并在已有工具结果的基础上显示简短结果说明。预算估算使用序列化UTF-8字节上界，并非模型的精确Token计数。

子任务返回短摘要及有限原文，完整过程仍保存在独立子会话中。“执行完成”与“证据充分”分开展示；资料不足或失败的任务会提示状态，并保留已取得的依据。并发委派的耗时按实际启动和结束记录。

联网搜索会检查问题主题，只有平台名或首页命中不会算作主题匹配；连续出现相同且偏题的候选时停止重复搜索。网页只取得入口链接时显示“仅取得入口链接”，允许继续读取真实入口，但不生成正文引用。自动标题跳过单纯问候，等首次实质问答完成后命名。

可通过环境变量或本机 `.env` 配置 `LLM_CONTEXT_WINDOW`（默认32768）、`LLM_MAX_OUTPUT_TOKENS`（默认4096）、`LLM_CONTEXT_MARGIN`（默认1024）。可用输入预算为三者相减，默认27648；输出上限会作为 `max_tokens` 传给模型服务。总预算必须大于输出预留与安全余量之和。

当前按 `messages`、工具定义和工具选择字段序列化后的UTF-8字节数做偏保守估算，不是官方Tokenizer的精确Token计数，也不能作为计费用量。默认32768是应用采用的配置，不代表某个模型的官方上下文上限；应按实际模型服务的输入、输出和上下文限制调整。保留安全余量也不能替代模型服务的最终校验。

聊天流程在每次模型请求前检查预算，包括工具执行后的再次请求。超过预算时按用户问题划分完整轮次，从最旧一轮开始移除，保留系统提示、最新问题及其工具调用和结果；只修改本次输入，不删除数据库历史，也不调用摘要模型。本轮附件检索/读取结果会生成单独的模型输入视图：重复片段保留引用并省略重复正文，必要时缩短正文并明确标记不完整及实际偏移；数据库和前端仍保存、显示完整结果。不会截断JSON、问题或工具调用配对。若必要输入仍装不下，则保存已有生成记录、标记失败并显示明确错误，不静默截断JSON或发送超出应用预算的请求。底层流式和单次请求也独立检查预算，避免其他调用入口绕过；单次 `/api/chat` 超预算返回400。

## TXT 文件上传

安装最新的 `backend/requirements.txt` 后重启后端，在 `http://127.0.0.1:8000/docs` 的“文件管理”分组测试：

- `POST /api/files`：通过 `multipart/form-data` 的 `file` 字段上传文件，成功返回 201 和文件基本信息。
- `GET /api/files`：获取全部文件基本信息，按更新时间倒序排列，数据库查询不加载正文和磁盘路径。
- `GET /api/files/{file_id}`：查询文件信息和处理状态。
- `DELETE /api/files/{file_id}`：删除文件记录、原文件、切片及相关向量，成功返回204；文件正在处理、排队建立索引或计算索引时返回409。允许删除已被聊天引用的文件，历史附件保留快照并标记已删除。
- `POST /api/files/{file_id}/index`：预约向量索引任务，返回202及文件状态；返回成功只表示任务已安排，不代表索引已经完成。
- `GET /api/files/{file_id}/content`：查询已提取正文；未处理成功时返回 409。

目前只支持 UTF-8（含 BOM）编码的 `.txt`，处理时最多读取 5MB；不接受空文件、纯空白内容或包含空字符的二进制内容。类型与大小错误返回 400 或 413；已经进入处理流程的失败文件会保留失败记录，并尝试清理未完成的磁盘文件。这个大小检查发生在框架接收 multipart 之后，不是整个 HTTP 请求体的入口限制。

原文件以随机 ID 命名，存放在 `backend/data/uploads`，文件信息和提取正文存入 `files` 表。基本信息接口不返回磁盘路径和完整正文。

聊天页面右侧的资料面板支持选择 TXT、上传、刷新状态和按需预览正文。页面打开时自动加载文件列表，默认选择最近一份；点击历史文件名可切换预览，每行右侧“×”用于删除，点击后会确认。列表刷新优先保留当前选择，切换文件时清理旧正文；上传失败或预览失败时保留原成功数据。上传成功后自动安排后台向量索引，存在处理、排队或建立中的任务时，页面每2秒自动刷新文件状态；全部完成或失败后停止，操作文件期间暂停，离开页面时取消查询。刷新会保留当前选择和正文预览；网络失败时提示并继续重试。仍可手动刷新，索引失败可用“建立 / 重试索引”重新提交。向量模型在启动阶段尝试准备，若准备失败，索引任务会再次尝试。正文处理和索引状态分别展示，索引失败不影响读取原文。上传文件不会自动作为附件，需要点击“添加到本次问题”。聊天模型可调用检索工具查找相关片段，也可使用原文读取工具查看全文或上下文。

删除当前文件后自动选择剩余第一份，没有剩余文件时清空预览，同时移除该文件在输入区中的待发送附件选择。历史消息保留原文件ID、名称和大小，并显示“文件已删除”，不要求删除会话；原文件不能再读取，但已有聊天正文及工具结果仍保留。删除采用数据库事务与上传目录内暂存：数据库提交失败时恢复原文件及活跃关联，提交成功后清理暂存文件；极端情况下清理暂存文件失败会记录后端日志。原文件已经缺失时仍可清理数据库残留，上传目录外的路径和目录不会被删除。

旧版本数据库请停止后端后，通过 `python -m backend.app.core.db_setup --upgrade` 备份并升级。附件迁移保留 `file_id` 作为历史ID快照，增加可置空的 `linked_file_id` 外键并回填现有文件；删除文件时只清空活跃外键。存在已删除附件快照时，迁移会拒绝无法无损完成的降级。

## 聊天附件关联（后端）

保存用户消息的 `POST /api/chats/{chat_id}/messages` 支持可选字段 `file_ids`，最多传3个已处理完成的文件ID。例如：`{"content":"总结资料","file_ids":["文件ID"]}`。未传时保持原来的纯文本聊天行为。

消息与附件关联在同一事务中保存，附件ID按选择顺序去重；文件不存在、处理未完成或处理失败时返回400，不会留下半条消息。消息接口和历史分页会返回 `attachments`，包含文件ID、发送时的名称及大小。删除会话只清理消息与附件关联，不删除已上传的原文件。

文件面板中的“添加到本次问题”可将处理成功的文件加入输入区，最多3份，发送前可以移除选择。保存问题失败时保留正文和附件草稿；保存成功后清空选择，模型生成失败时重试不会重复保存问题。新建、切换或删除当前会话成功后清理附件草稿，历史消息会展示已保存的附件名称和大小。

模型输入会包含已完成用户历史中附件的ID、名称和大小，正文通过 `read_uploaded_file` 工具按需读取。无附件时不提供读取工具；读取范围仅限本次模型历史中关联的文件，模型不能覆盖后端数据库连接或允许的文件范围。默认每次读取6000字符，最多12000字符，使用 `offset` / `next_offset` 继续读取，`has_more` 表示是否还有剩余内容。这里按字符计数，不是Token预算；保留最多5次模型请求的现有限制，长文档可能无法在一次回答中读完。

前端工具区域会显示“读取附件正文”或“检索附件内容”。读取结果显示原文及分页信息，检索结果显示可折叠的文件来源、片段和原文偏移，同时保留原始调用JSON。调用和结果保存到助手 `output`，后续对话可还原，不会重新执行历史检索。表结构变化由初始化及迁移流程管理，旧数据库需要按启动提示升级。

## 文件文本切片（后端）

新上传的 TXT 在提取正文后自动切片，默认每块最多1000个字符、相邻块重叠150个字符，保留空格和换行。位置从0开始，`start_offset` 包含、`end_offset` 不包含；按字符计算，不是字节或Token。例如2500字符会产生 `[0,1000)`、`[850,1850)`、`[1700,2500)` 三块。

完整正文保存在 `files`，切片保存在 `file_chunks` 表。正文、处理状态和切片使用同一个事务提交；切片写入失败时不会留下已完成但只写入部分切片的文件。建立索引时会按当前模型的Token窗口自动补建或调整切片。

- `GET /api/files/{file_id}/chunks?offset=0&limit=20`：按块序号分页查看切片，默认20块，最多100块，返回 `items`、`total`、`offset`、`limit`。查询不读取原始全文。
- `POST /api/files/{file_id}/chunks`：为已经处理成功的文件补建或重建切片，返回 `file_id` 和 `chunk_count`，同时预约新向量索引。重建会替换旧切片，重复执行不叠加；SQL失败时回滚并保留原切片，后续向量任务失败时保留新切片并显示索引失败。已有索引任务时返回409。

可在接口文档的“文件管理”分组测试。当前没有前端切片查看入口；现有 `read_uploaded_file` 工具仍按偏移读取原文，不自动改为切片检索。

## 本地向量与文件索引

`backend/app/rag/embedding.py` 提供 `prepare_embedding_model()`、`embed_texts()` 和 `embed_query()`：使用 Sentence Transformers 在本机计算向量，默认模型为 `BAAI/bge-small-zh-v1.5`，默认使用CPU。后端先完成数据库检查和中断恢复，再在启动阶段等待向量模型准备；先以local_files_only方式加载本地模型；已有完整缓存时不联网检查，只有本地加载报告缓存缺失时才尝试联网下载，首次启动可能较慢。也可将 `EMBEDDING_MODEL` 设置为已准备好的本地模型目录。模型准备和计算在线程中执行，不阻塞事件循环，但启动准备结束前应用尚未进入接收请求阶段。

启动准备成功后，索引和检索复用进程内的模型，不重复加载；进程退出后内存释放，重启需要再次加载。下载或加载失败会写后端错误日志，应用仍继续启动，普通聊天不依赖向量模型；后续实际索引或检索仍会尝试加载。准备模型不会自动给旧文件建立索引，也不会创建向量集合；数据库检查失败时不会进入模型准备阶段。

可通过环境变量或本机 `.env` 设置 `EMBEDDING_MODEL`、`EMBEDDING_DEVICE`、`EMBEDDING_QUERY_PREFIX`，修改后重启后端。默认查询提示用于BGE中文模型，文件片段不加该提示；更换其他模型时应按模型要求调整或清空查询提示。

`backend/app/rag/vector_store.py` 提供切片向量批量写入、按文件范围查询和删除。ChromaDB首次使用时创建 `backend/data/vector_db`，显式使用我们计算的向量，不调用Chroma默认向量模型。同一配置的文件切片共用集合，通过 `file_id` 限定查询范围；模型标识、查询提示或切片策略版本改变会使用不同集合，需要重新建立索引。若覆盖同一路径下的模型权重，也应重新建立索引。查询返回距离，余弦距离越小表示越接近，不是概率或百分比。

上传后先提交正文及内容指纹，再预约FastAPI后台任务；请求阶段不再生成字符切片；后台使用独立数据库会话，先用模型分词器将原文调整为最多384 Token、重叠48 Token的窗口（模型上限更小时相应缩小），保留原文字符偏移，并在向量计算前校验实际Token数量，禁止静默截断；每批读取32个切片，在线程中计算向量和写入ChromaDB。文件的 `status` 记录文字处理，`index_status` 单独记录 `pending/indexing/ready/failed`。`index_task_id` 在预约时写入数据库以拦截重复提交，旧任务不能覆盖新任务结果；仅全部成功后才记录ready及当前配置的 `index_key`。更换模型后，接口将旧配置的ready显示为pending，需手动重建。失败和取消会尝试清理半成品，并释放任务供重试；原文与切片不删除。

已有文件升级后保持pending，不批量建立索引；启动准备模型不会自动处理这些文件。没有切片的旧文件可直接建立索引，由任务补建。任务排队或计算期间禁止删除、替换正文及重新切片；切片内容和偏移未改变时重建索引保留切片ID；切片策略变化时替换旧切片。此次索引策略升级后，旧索引需点击“建立 / 重试索引”，或在知识库点击“更新本库索引”批量更新；数据库需升级至 `c4f9b2d7e165`。删除文件先提交SQL事务，再清理各模型集合中该文件的向量，避免SQL回滚破坏原索引；SQL删除与 `file_cleanup_jobs` 清理待办在同一事务提交；提交失败不会碰原文件或向量。提交后立即清理原文件及所有模型集合中的向量，失败时持久保留待办及退避时间，后台每30秒扫描最多20个到期任务，重启后继续。检索仍核对SQL中文件存在、切片有效及索引ready。 删除文件后，若集合已空，会通过Chroma删除集合并清除集合对象缓存；其他文件仍在使用的集合保留。Chroma 1.5.9可能保留已删除集合的物理索引目录，应用会只读核对其segments元数据，回收不再被任何索引引用且路径位于vector_db内的UUID目录，保留数据库文件。文件被占用时记录日志，下次启动重试；启动时也会清理此前留下的空集合。写入、查询和回收使用同一个进程锁，避免并发误删。此机制不压缩仍在使用的集合或SQLite数据库文件。

当前使用单后端进程的进程内后台任务，不是持久化任务队列，请勿使用多个Uvicorn worker运行。服务启动时会把遗留排队和计算任务标为failed，允许手动重试，不会自动续跑。“可检索”表示当前向量配置下索引已准备好，聊天是否调用工具由模型决定。

本批迁移版本为 `c8f3b6a0d921`。旧数据库请先停止后端，在项目根目录执行 `python -m backend.app.core.db_setup --upgrade`，命令会先备份，再增加索引状态字段；之后重新启动。迁移不会生成向量或下载模型。

测试使用模拟向量模型和临时ChromaDB，验证参数、线程计算、模型复用、文件范围过滤、重复写入、跨进程持久化和删除；没有下载真实模型权重或修改现有文件、聊天数据。

## 聊天附件检索

`search_uploaded_files(query, file_id?, limit=5, file_ids?)` 已注册为模型工具：查找具体条款或事实时优先检索，完整汇总、查看前后文时使用 `read_uploaded_file`。省略file_id搜索本次允许使用的全部附件，指定file_id只能缩小范围。没有附件时不提供附件工具。查询文字最长1000字符，limit为1到10；自动资料准备会在普通具体问题中调用该工具；file_ids可限定多个文件，且与file_id互斥。所有范围必须属于后端允许集合；不额外调用模型生成检索词。

`backend/app/rag/retrieval.py` 是公共检索层：先检查文件存在、文字完成、索引ready、当前模型配置一致且无索引任务，再计算问题向量并在线程中查询ChromaDB。可用附件与不可用附件分别处理，返回 `unavailable_files` 明确指出文件不存在、索引未完成、失败或模型变化，不把这些情况当成没有匹配。实际查询不会自动创建缺失的向量集合，模型或向量库异常返回固定错误，不暴露路径和内部配置；取消操作继续向上传播。

查询后再次核对SQL文件状态及切片ID，正文、文件名、切片序号和原文位置来自SQL，忽略向量库可能过期的正文及元数据。按融合后的排名返回，过滤重复正文、孤立或越界切片和无效距离。默认最多返回5个片段，正文合计最多5000字符，超出时返回truncated并记录实际返回内容的end_offset；原文偏移从0开始，终点不包含。检索候选不代表读完全文或必然相关，余弦距离不是正确率。关键词和向量共同召回，再用RRF合并排名。SQL在允许范围内选最多512个关键词候选，以中文二元词片段和完整英文/编号进行BM25排序；向量召回最多50个候选。FT-204等精确位号优先，并排除FT-2040这类相似编号误命中，但保留其他相关语义条款。match_type区分exact/hybrid/keyword/semantic；distance仅来自实际语义结果，纯关键词候选为null。纯语义候选超过 `RETRIEVAL_MAX_DISTANCE`（默认0.75）会被过滤，此阈值需要结合实际模型与资料调校。向量服务失败但关键词有命中时降级返回并注明。当前没有额外重排模型，关键词候选采用有上限的SQL扫描，不是全库全文检索引擎。

上下文裁剪后，会重新计算剩余用户消息携带的附件范围及工具定义开销。授权来自数据库中的真实附件关联，不解析用户自行编写的文件清单或工具返回文本作为授权。已有工具结果仍作为历史内容保存，原文件删除后不能继续读取。助手回答可说明依据的文件名；正文内的可点击来源引用尚未实现。

检索接入不增加数据库字段，继续使用上一批的 `c8f3b6a0d921` 版本。真实存储闭环测试使用临时SQL和ChromaDB、模拟向量及聊天模型，验证工具回传、SSE、output保存和历史还原；不代表真实模型权重和外部API已经完成联调。

## 回答中的附件来源引用

附件检索和原文读取结果由后端分配本条助手回答内的 `citation_id`，同一文件、位置和正文重复返回时沿用编号。模型按 `[1]` 格式引用；前端只将实际工具结果中的编号渲染为可点击按钮，未知编号、代码及普通链接不转换。

点击编号或展开“本轮资料来源”，可查看随工具结果保存的原文快照；快照复用现有消息 `output` 存储和流式事件，无需新增表或数据库迁移。来源列表包含本轮返回的候选资料，不表示每段均被答案采用，也不保证模型推理正确。

引用面板按需检查原文件状态，可点击“查看全文并定位”读取全文并高亮引用位置；中文和emoji按后端Unicode字符偏移定位。只有当前原文与快照一致时才高亮。原文件404时标注“原文件已删除”并保留快照，网络错误则提供重新检查，不冒充文件删除。关闭面板或离开消息时取消请求。

此功能对新生成的带来源编号回答生效；旧记录没有后端编号时保持原样，不猜测或补造引用。

## 每个账号的模型服务设置

侧栏点击“设置”或点击顶部模型名称，可设置当前账号的一套模型服务配置。提供服务器默认、DeepSeek、OpenAI、通义千问、Ollama及自定义服务；自定义需要兼容OpenAI的 `/chat/completions` 接口，也支持显式选择无需Key的本地服务。官方选项只预填服务地址，不预填固定模型；模型由服务实际返回的列表选择或用户手动填写。输入区模型列表不混入当前保存的旧模型；旧模型不在列表时单独提示，并支持搜索真实返回的模型。

可填写API基础地址、模型ID、请求超时（5～600秒）和个人API Key。获取模型列表调用 `/models`，成功后在“可用模型”下拉框直接展示所有返回模型，并自动滚动到选择区域；选择后同步模型ID，也可手动修改，保存配置后生效。不支持该接口时可手动输入模型ID。测试连接发送一条简短非流式请求，最多请求512个输出Token，可能产生少量费用；测试提示要求直接短答；若模型仅在思考阶段耗尽预算，会单独提示已连接但尚未验证最终正文，不误判为不支持聊天。测试只验证文本聊天响应，不验证工具调用或附件检索，也不会保存草稿。保存本身不访问模型服务；保存后仅影响当前账号的新回答，已经开始的回答及其工具循环继续使用开始时的配置快照。

个人设置优先于服务器环境默认值，其他账号无法读取或修改。未保存个人设置或恢复默认时，继续使用服务器的 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_TIMEOUT` 和 `DEEPSEEK_API_KEY`。服务器共用Key只能发往服务器默认地址，不能通过自定义地址转发。输入预算、输出上限和安全余量暂时仍由服务器环境配置，不在本次设置面板修改。

个人Key用Fernet认证加密后保存到 `user_model_settings.encrypted_api_key`，读取设置只返回是否已经配置，永不返回明文或密文。留空只在服务地址不变时保留已保存Key；更换地址需要重新填写。恢复服务器默认会删除当前账号保存的个人配置和Key密文。表单关闭或保存成功后清空输入，不写入localStorage。API参数校验失败也不回显Key或密码输入。

加密主密钥与数据库分开保存。可在服务器环境设置固定的 `MODEL_CONFIG_ENCRYPTION_KEY`（Fernet格式）；未设置时，首次保存个人Key会在 `backend/data/secrets/model-settings.key` 自动生成并持久保存。本地数据目录及 `*.key` 已被Git忽略。备份、搬迁时需要同时保留数据库与对应主密钥；主密钥丢失后无法解密旧Key，需要用户重新填写。修改主密钥不是自动轮换操作，不应直接替换正在使用的密钥。

本次新增 `user_model_settings` 表，旧库需停止后端后执行 `python -m backend.app.core.db_setup --upgrade`，命令先备份。然后重启前后端；未保存个人配置的账号保持服务器默认行为。没有在正式数据库自动创建个人模型配置，也没有自动调用任何外部付费模型。

设置、账号与引用弹窗支持点击外侧遮罩或按Esc关闭；内部点击、从内部选中文字拖到外侧不会误关闭。账号菜单与输入区模型菜单在点击外侧时收起。输入区快捷选择只更新本人模型名称，若服务地址已经变化则要求重新获取列表，避免覆盖其他标签页修改的服务和Key。

Ollama预设自动填入 `http://127.0.0.1:11434/v1`、选择无需Key，并至少预留120秒超时；仍从服务读取模型ID，不预填固定型号。对明确为Ollama的服务，会通过同一服务的 `/api/show` 查询能力元数据，最多并发4个、总等待3秒，不加载模型或发起推理。明确只有embedding能力的模型从聊天列表隐藏；同时支持completion的模型保留，查询失败或用途未知的模型也保留并提示。设置与输入区同时展示过滤说明及工具、思考能力标签，能力标签来自服务声明，不代表已经验证实际生成质量。

模型设置显示未保存状态，修改字段后会清除上次测试提示。连接测试等待时间采用配置值，最多120秒；模型列表等待最多20秒。认证失败、权限不足、接口不存在、限流和服务故障分别提示，避免把所有错误归结为模型名称或Key。

聊天操作支持直接拖入本地TXT或资料空间里的历史文件，也可以在输入框粘贴剪贴板文件，统一遵守5MB和每条消息3份附件限制。历史资料按ID引用，不重复上传或建立索引；资料列表支持搜索、逐行添加和已选标记。输入框“＋”提供本地上传与已有资料两个入口，上传期间可继续编辑正文，完成前暂缓发送。

模型配置保存成功后自动关闭设置、显示短暂成功提示并返回输入框；失败保留表单和错误提示。向上阅读对话时显示“回到最新消息”。手机端资料空间采用侧边抽屉，点击遮罩或按Esc关闭。本轮交互调整不涉及数据库升级。

### 个人知识库

左侧“知识库”进入管理面板，支持创建、修改名称和简介、上传TXT、加入已有资料、移出文件以及重试索引。每库最多200份文件；同一原文件可以属于多个库，复用已有正文、切片和向量索引。索引处理中会自动更新状态，失败原因单独显示。个人知识库仅所属账号可见，管理员也不能读取其他账号的库。

创建或选择知识库后，可以把多份本地TXT直接拖入面板，或点击虚线上传区点选，上传时显示批次进度。展开“加入已有资料”后，也可把已有文件拖入上传区，仅创建关联、不重复上传。两种本地上传入口共用格式、单文件5MB及每库200份的校验；压缩包需要先解压。未选库或正在处理其他操作时会拒绝拖入并说明原因。

在输入框“＋ → 选择知识库”中勾选并应用，每个会话最多5个；输入框上方显示库标签，可随时移除。空白页可以先选择，第一次发送时与新会话原子保存。所选库随会话保存，刷新或重新打开会话后恢复。正在回答时不能切换会话的知识库配置。

检索范围为当前会话资料与会话选中知识库中的文件，不自动搜索账号下全部文件。普通附件发送成功后也会成为会话资料，持续用于追问，直到用户明确移出或永久删除原文件。本轮只使用生成开始时已允许的文件，每次工具执行前重新核对关联及所有者，移出文件或删库会撤销对应入口的后续读取权限；新加入的文件在下一次回答使用。已进入回答的工具结果属于历史快照，不会因移出文件而被回写删除。

移出资料或删除知识库只解除关系，不删除原文件和索引；永久删除原文件才按已有流程清理正文、切片与向量，同时解除所有库成员关系。历史回答的引用编号、文件名、原文快照和定位继续使用已有持久化机制；删库后原文件仍在，可以继续打开原文。

## 网页读取

可以直接发送“读取这个网页并总结：https://example.com”，也可通过输入框“＋ → 引用网页”先把链接加入草稿。发送后，支持工具调用的模型可使用 `read_webpage(url, offset=0, max_chars=5000)` 读取网页；需要后文时按next_offset分页，每次最多12000字符。优先读取静态HTML或纯文本；HTML正文为空或提示需启用JavaScript时，自动回退到Playwright Chromium执行页面脚本，等待可见正文稳定后提取。工具移除脚本、样式和常见导航，优先使用main/article正文，不携带登录Cookie或模型API Key。

聊天中的地址必须来自当前可用用户消息内明确给出的链接、真实搜索结果、已抓取网页的最终地址或既有网页来源；模型不能自行增加查询参数或拼接其他目标。普通网页重定向仍按公开网络规则逐跳校验。这里的链接授权来自数据库中的真实消息及工具结果，不接受模型在工具参数中覆盖history或其他后端上下文。

每轮最多抓取5个不同链接，分页复用该轮已抓取内容；下一轮重新调用网页工具会重新抓取。仅访问80/443端口的公开HTTP/HTTPS地址，拒绝URL凭据、非公开IP及混合公网/内网DNS结果；连接固定到已验证IP，Host和TLS校验仍使用原域名，每次重定向重新验证。工具不读取环境代理。静态响应最多1MB、最多5次重定向；浏览器的脚本、接口及跳转也由后端逐次校验后转发，单资源最多8MB、总量32MB、最多100个请求及6次主页面导航，阻止图片、媒体、字体、子框架、Worker和WebSocket。浏览器阶段最多40秒，整次读取最多60秒；单进程最多并行2个浏览器任务，每次任务独立启动并关闭浏览器，不复用用户会话。Windows下在独立线程中运行，兼容uvicorn --reload。登录、验证、正文为空或加载失败会明确报错，不绕过限制；正文提取可能不完整，页面稳定不等同于已取得全部内容。

安装后端依赖后，使用运行后端的同一Python环境执行 `python -m playwright install chromium` 下载浏览器，再重启后端。Linux部署可执行 `python -m playwright install --with-deps chromium` 安装系统依赖。`WEB_BROWSER_ENABLED` 默认true，设为false可关闭浏览器回退；缺少依赖或浏览器时会提示安装命令，不阻止静态网页读取。此次浏览器读取无需数据库迁移。

正文提取使用trafilatura和可见性/导航过滤，保留段落、标题和表格；菜单密集或仅有加载提示的页面也会尝试浏览器，渲染后仍无有效正文则明确报错。分享对话按消息顺序提取，避免通用文章提取只留下第一轮。links提供页面中真实存在的候选链接，后续及历史回答可据此继续读取，每次访问仍重新检查公网地址。网页工具记录本轮已返回区间，完全重复读取不再返回第二份正文；部分重叠只补充未读部分。范围以模型实际收到的预算视图为准，避免截短后无法续读。相同链接本轮失败后不重复发出网络请求；完全包含的引用范围沿用原编号。

网页来源使用[1]等编号，点击可查看当时返回的提取正文、读取时间与原始链接。已返回片段随回答output保存，重新打开会话仍可查看；历史来源工具可以重新引用这些快照，且与新抓取的网页区分。网页不自动变成上传文件、不加入知识库或向量库，也不保存完整HTML；只有本轮返回的正文片段进入历史。此次无需数据库迁移。

## 联网搜索

在输入框“＋ → 联网搜索”开启当前会话的搜索能力，输入框会显示可点击关闭的“联网搜索”标记，不改写问题或插入提示词。新会话默认关闭，开启后首次发送才创建会话；已有会话保存开关，重新打开时恢复。开启表示允许模型按需搜索，不强制每轮搜索；关闭时不向模型提供搜索工具，也拒绝执行该工具。服务器总开关也必须开启。

`search_web(query, count=5)` 返回标题、链接和摘要，最多10条候选；模型需要依据时继续调用 `read_webpage` 读取真实搜索结果。搜索候选显示专用卡片，并明确注明尚未读取原文；搜索结果不分配引用编号、不进入知识库或向量库，只有成功读取的网页正文才产生引用。

默认使用免Key的Bing公开RSS入口，实测可返回结果；它不是付费Bing搜索API，公开入口的可用性和结果数量可能变化。也支持DuckDuckGo HTML入口、Tavily和Brave。免费入口受网络、访问验证或页面格式变化影响时会明确报错，不会伪装成搜索成功或没有结果，也不会静默改用另一个提供方。

以下为服务器级配置，所有账号共用搜索提供方，与每个用户自己的模型服务配置分开：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| WEB_SEARCH_ENABLED | true | 服务器总开关；还需开启当前会话的联网搜索，false时所有会话均不可搜索 |
| WEB_SEARCH_PROVIDER | bing | 可选bing、duckduckgo、tavily、brave |
| WEB_SEARCH_API_KEY | 空 | 仅Tavily/Brave需要；不复用DEEPSEEK_API_KEY或个人模型Key |

修改环境配置后重启后端。Tavily/Brave适配使用模拟响应验证，开发验证未使用真实付费Key。搜索请求固定到已验证的公开IP，使用原域名进行Host和TLS校验，不读取环境代理；免费入口仅允许同提供方内的有限HTTPS重定向，带Key的API请求不跟随重定向。响应大小及解压限制复用网页读取规则，每次工具总超时30秒，每轮最多3次搜索尝试；相同关键词和数量的成功结果在该轮复用，下一轮重新请求。

搜索结果带轻量主题重合信号quality及剩余attempts_remaining；低相关候选仍保留原始结果并明确警告，提示缩短查询、保留核心主题或由管理员配置其他提供方，不静默切换服务。此信号不是准确率或重排模型。搜索额度耗尽后从后续模型请求的工具清单移除；执行入口仍强制检查限额。单次回答最多实际执行12次工具（含自动准备），达到后要求基于已有资料回答，同批次超额调用返回明确原因。每轮提供当前日期、搜索开关及剩余额度，避免模型无依据地解释“换了环境”或随意使用旧年份。

真实返回的结果URL会加入该轮允许读取范围；重新打开会话后，网页工具也可从已保存的成功搜索结果恢复这些URL。不能通过修改查询参数、伪造候选或传入后端上下文来扩大范围。模型输入预算不足时可缩短摘要或省略靠后的候选，完整结果继续保留在output中；历史卡片保留当时的搜索内容，不表示仍然是最新结果。

## 回答与处理过程

最终正文与模型返回的reasoning_content/reasoning/thinking字符串分开传输、保存和展示，不根据普通正文伪造思考。模型未返回独立思考字段时不显示“模型思考”。工具调用前的文字作为过程说明保存，最终content仅包含回答；旧记录根据结构化轮次分离展示，不回写旧数据库。过程默认收起为一行，生成时展开；内部按顺序显示思考、过程说明及紧凑工具行，原始参数和结果仍可展开查看。较长过程限制面板高度，手机端不横向溢出。

消息底部提供复制回答及简短时分，完整日期和模型名称悬停查看。工具耗时及整轮耗时以毫秒记录在已有output JSON中，刷新后仍可恢复；旧消息缺少详细计时时采用消息起止时间。每轮保存turn_metadata（开关、可用工具、起始时间和耗时），不包含Key或认证信息。此次展示和调度调整无需新增数据库迁移。

## 自动会话标题

新会话首次发送后暂用“新会话”；首轮回答成功保存后，后台沿用本次回答的用户模型连接，额外发起一次简短的非流式命名请求，依据第一条问题与首轮最终回答生成标题。命名不携带思考或工具全文，不调用搜索等工具，不在工具历史显示，不等待标题再结束聊天流。通常4～16个汉字，最多32字符。后续聊天不反复改名；自行指定名称或通过改名接口保存的标题始终由用户控制，即使手动改回“新会话”也不会被后台结果覆盖。

`chats.title_status` 记录pending/generating/generated/fallback/manual；模型超时、不可用或返回格式不合适时，使用首条问题的简短文本兜底，不把标题错误当作聊天失败。后台最多并行两个命名请求，排队与生成总等待最多30秒，单次HTTP超时最多20秒；不自动重试计费请求。关闭时清理任务，重启后对中断的命名使用首条问题兜底。更新标题使用条件写入，手动改名或删除会话后，迟到结果不覆盖或恢复数据；命名不改变会话排序时间。

回答完成后前端独立查询标题状态，更新侧栏与当前会话；不会禁用输入或覆盖新选的文件、知识库及搜索设置。离开账号/销毁仓库、手动改名或删除会话时停止相应查询。此功能新增迁移 `e6b1d4f9a387`，旧会话统一保留原名、不批量补写；升级前停止后端，在项目根目录运行 `python -m backend.app.core.db_setup --upgrade`，然后重启后端、刷新前端。

## 子智能体

主模型通过 `delegate_task` 委派独立任务，后端直接复用 `stream_chat_history_events` 聊天引擎创建子运行，不通过HTTP请求自己。模型、工具执行器及消息持久化共用；子会话、Session、上下文、工具缓存和引用编号独立。默认前台等待，`background=true`立即返回任务编号，完成后等待主会话空闲，自动形成一条“子任务更新”回答。后台结果通过真实的get_subagent_task读取进入主模型，不伪造用户问题。用户发送消息优先，后台续答不会覆盖正在进行的用户回答。

示例：“请用两个子智能体分别核对这两个网站，再汇总比较”。模型同批返回的多个delegate_task会先分别登记，再并发启动；普通工具继续按原顺序执行。实际模型服务可能自行排队，子任务会产生额外模型请求。默认沿用当前用户的本轮模型连接，不提供任意URL或Key参数。

工具位于 `tools/local/delegate_task.py`，后端运行管理位于 `chat/subagents.py`；get_subagent_task查询结果，cancel_subagent_task停止任务。子任务只能获得明确传入的file_ids、history_source_ids，以及父模型可用工具的子集；省略文件表示不分配文件。父会话移除资料或关闭搜索后撤销后续访问；委派文本中的网址必须核对父会话真实授权，不能冒充原始用户输入扩大范围。工具清单和执行入口都禁止递归派生。

子会话保存完整用户任务、思考、工具调用、工具结果、最终回答及错误；普通侧栏不显示子会话，主会话工具行可“查看过程”或“停止”。历史通过所属主会话只读分页访问，跨账号、跨主会话查询被拒绝。引用从子任务真实来源取快照，在主回答重新编号，不复制整段子历史进主上下文。刷新后通过数据库恢复任务与历史，任务行轻量查询状态；后台汇总完成会刷新当前会话，保留输入草稿和已加载旧消息。

`SUBAGENTS_ENABLED` 默认true，设false停止开放新委派；`SUBAGENT_TIMEOUT` 默认300秒，范围10～1800秒。单次主回答最多4个子任务，同账号最多8个待完成任务，执行时同账号并发2个、单进程并发4个；队列等待有超时。停止主回答会取消关联前台子任务，后台任务保持独立，可逐项停止。删除主会话会停止相关任务并在同一事务删除主子历史和任务记录，不删除用户原文件或共享索引。重启后保留已存历史并标记中断，不自动重复发出计费请求；未成功自动汇总的结果仍可通过任务记录查看。

当前运行协调适用于单后端进程，不声称具备多worker分布式调度。新增迁移 `f7c2e5a0b498`，旧会话kind默认为conversation；停止后端执行 `python -m backend.app.core.db_setup --upgrade` 后重启。开发检查使用隔离数据库、模拟模型和界面预览，不自动升级实际用户库。
